# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| plan-scope-match | The diff's changed files and hunks (`git diff main...HEAD` live; the candidate PR's diff in eval) read against the plan's stated scope and boundary (its Files line and "not in scope" line, plus any `## Deviations` note in plan.md). | Every changed file and hunk falls inside the plan's stated boundary, or is named in a deviation note that explains why it is there. Any hunk outside both fails. | required |
| deliverables-present | Each deliverable the plan promises (each fix, guard, warning, doc update, test, or setting the plan lists under scope) read against the diff. | Every promised deliverable appears in the diff, or is named as deferred or dropped in the plan's deviation notes and in the PR description. A promised deliverable that is neither in the diff nor disclosed fails. | required |
| description-fidelity | Each claim in the PR title and description (for example "implements the plan exactly", "no changes beyond", "docs now document X", "rendering unchanged") read against the diff and the plan. | Every fidelity or scope claim in the description is supported by the diff and the plan. A claim the diff contradicts or does not contain (more or less than the diff delivers, or "no other changes" when extra hunks exist) fails. | required |
| repro-before-after | The test evidence (test_evidence.md live; the candidate PR's test-evidence section in eval) read against the plan's repro and test plan: the failing case the issue reports and the plan's expected-after. | The failing case the plan names (the issue's own repro, and each separate failure mode the plan's test plan lists) is shown before and after the change with observable output or a concrete observed result, on the path the change touches, and the after matches the plan's expected-after. Fail if the repro is never shown ("tested locally", "works now"), only an unchanged path or easy control is shown, or a failing case the plan names is never re-run. A secondary control or smoke check described in prose is fine. | required |
| repo-checks-run | The repo's own checks named by the PR template, the repo-facts block's asks, or the plan's test plan (live: make test-unit, make test-integration, make lint, make typecheck) read against the test evidence. | Each named check is reported with the command and its outcome (pasted output live; in eval a stated outcome such as "go test ./... passes" or "cargo test: 312 passed" is enough). Fail if a named check is never mentioned, or if it ran and failed and the failure is not reported with its reason. Live, "no tests ran" with its real output counts as run. | required |
| no-debris | The diff's added lines read for debug output (print, console.log, eprintln, dbg!), commented-out code blocks, dead functions or unused variables, TODO or FIXME left in the change, and unrelated formatting or import churn. | No added line is debug output, commented-out code, dead code, or unrelated churn. A pre-existing comment that the diff leaves untouched does not count. Any debris line fails. | required |
| template-sections | The repo's own PR asks read against the candidate description: live, the sections of .github/PULL_REQUEST_TEMPLATE.md (Summary, Issue, Changes, Testing, Screenshots / Demo, Notes for Reviewers); eval, the repo-facts block's template asks (a required checklist, a closes line, a changelog or whatsnew entry, a description section). | Every ask the repo states is answered with substance: prose that answers a checklist item counts, and a bracket-free "N/A" with a reason counts. Live, the Issue line also reads "Closes #<number>" matching the plan's issue. Fail if a stated section is empty or left as placeholder text, or a stated ask is visibly ignored (a required checklist absent, a required closes reference absent when the repo asks for one, a required changelog or whatsnew entry missing from the diff). Asks the repo does not state are not required. | required |
| testing-boxes-match-evidence | Each ticked box or claimed requirement in the description read against the test evidence. | No ticked box or claimed requirement is contradicted by the evidence, and none that names a check or test run is wholly unsupported by anything in the evidence. A claim backed by a stated outcome counts. The CI box may stay unticked. | preferred |
| ai-disclosure | The repo's stated AI-use policy (eval: the contribution policy line in the repo-facts block; live: docs/CONTRIBUTING.md, plus the course's own ask that Notes for Reviewers say how AI was used) read against the description. | Where the repo states a policy that requires disclosing AI use, the description contains a disclosure in the author's own words. Live, the Notes for Reviewers section must state how AI was used. Fail if a stated policy requires disclosure and the description has none, or it says "none" while the work was AI-assisted. Where the repo states no AI policy (eval), pass with the evidence "no stated AI policy"; do not invent one. | required |
| seeded-marker-removed | In live mode, the repo's tests and pyproject.toml read for any `xfail` marker or suppression that names the issue number (`grep -rn "issue #<n>:" tests` and pyproject.toml). In eval mode, the diff and the plan read for any xfail marker the plan names. | If a marker or suppression naming the issue exists on main, the diff removes it. If none exists, the check passes and its evidence line says none was found. | required |
| thread-direction-engaged | The issue's thread (live: the issue's comments; eval: thread highlights in the package) read for maintainer or reviewer direction on the change. | Any explicit direction in the thread (a requested approach, a named constraint, a question put to the author) is either followed in the diff or answered in the description. If the thread has no direction, the check passes with the evidence "no direction in thread". | preferred |
| deferrals-disclosed | Any planned work the diff leaves out (read from plan.md's deviation notes, or the plan's scope-out line) read against the PR description. | Each deferral named in the plan appears in the description with a reason. An honest deferral is not a failure. | preferred |

## Verdict rule

- Accept (ready to submit) when every `required` check grades `pass`.
- Reject (hold) when any `required` check grades `fail`, or when any `required` check grades `unclear`.
- `preferred` checks never change the verdict, whatever their grade.
- `unclear` is treated as `fail` for every `required` check. A claim the package cannot verify is a claim that is not ready to submit.
- A PR that discloses a shortfall in plan.md's deviation notes and in its description can still pass plan-scope-match, deliverables-present, and description-fidelity. Disclosure is the honest path. "Less than everything" alone is not a reason to hold.
